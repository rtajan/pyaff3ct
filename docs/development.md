# Development

## Repository

| Path | Content |
|---|---|
| `aff3ct/` | the Python package; `aff3ct/_ext` is the compiled extension |
| `internal/src/Wrapper/` | the pybind11 bindings, one directory per family of modules |
| `lib/aff3ct` | AFF3CT (git submodule), with its references (`refs`) and configuration files (`conf`) |
| `examples/` | the scripts of this documentation, run by the tests |
| `tests/` | the test suite, including `test_references.py` (33 AFF3CT references rebuilt from their command lines) and `test_examples.py` |
| `scripts/` | build helpers, generation of the design documents and of the figures |
| `Plan.md` | architecture, wrapping rules and roadmap |

## Development build

```bash
PYTHON=path/to/python scripts/dev_build.sh       # build/dev, aff3ct/_ext*.so linked in the source tree
path/to/python -m pytest -n 4
```

## Documentation

The pages are in `docs/`, written in Markdown for [MkDocs Material](https://squidfunk.github.io/mkdocs-material/).

- Code is never written in a page: it is included from `examples/*.py` between section markers,
  `# --8<-- [start:name]` and `# --8<-- [end:name]`, with `--8<-- "examples/script.py:name"`. The examples are
  imported and checked by `tests/test_examples.py`.
- Short interactive blocks (`>>>`) are doctests, run by `tests/test_docs.py`.
- The figures (`docs/assets/figures/*.svg`) are computed by the examples: `python scripts/doc_figures.py` (not
  versioned, generated by the CI).
- `mkdocs build --strict` fails on a broken link or a missing snippet.

```bash
pip install ".[docs]" --no-build-isolation
python scripts/doc_figures.py --threads 4
mkdocs serve
```

## Versions and releases

The version comes from the git tags (`setuptools_scm`): a build at the tag `v0.2.0` is `0.2.0`, a build 3 commits
later `0.2.0.post3+g<hash>`. Changes are listed in `CHANGELOG.md`, section *Unreleased*, in each merge request.

To release a version:

1. in `CHANGELOG.md`, rename *Unreleased* to the version and its date, and open a new empty *Unreleased* section;
2. merge, then tag the merge commit of `main` and push the tag:

   ```bash
   git checkout main && git pull
   git tag -a v0.2.0 -m "pyAFF3CT 0.2.0"
   git push origin v0.2.0
   ```

The wheels are not published on PyPI yet.
